# 精進ボードの全体点検(2026-10-09)

2026-10-09 時点の精進ボード(3bc6b2f)について、実装の不具合と、想定と違う挙動を PC・スマホの両方で点検した記録。
コードを読んで候補を挙げ、Playwright で本番(GitHub Pages)を実際に動かして確かめてから直した。

## まとめ

- **実際に起きていた重い不具合**: 次の 6 件を、本番で再現してから直した。
  - **実力推定**: A 問題を中心に解き、B 問題で未AC がある初心者は推定が上限 5000 に張り付き、「次に解く問題」が 0 件になる
  - **問題検索**: エディターの問題検索に日本語を変換しながら入力すると、入力欄が空のまま何も入らない
  - **計算量タブ**: 問題ページからコピーした「2×10 5」「2×10⁵」を 210 と読み、TLE するコードを「余裕」と判定する
  - **コーナーケース(グラフ)**: 密なグラフでは最大のケースがすべて失敗する。`\frac` を含む制約は生成が終わらない(40 秒以上)
  - **画面が真っ白になる**: デプロイをまたいで開いたままのタブで計算量タブを開くと、アプリ全体が消える
  - **コード欄(Windows)**: スクロールバーが幅を取る環境で一番下までスクロールすると、色付けの文字と行番号が入力位置から 15px ずれる
- **ほかに直したもの**: コーナーケースの制約違反(≠・偶奇・0 始まり・否定の言い回し・総和)、取得に失敗したあとの鮮度の表示、スマホの横向きでの入力時の拡大、ヒートマップの詳細が端で切れる・タップで出ない、テーマのちらつき、コントラストなど。
- **コミット**: 10 個(64584a8〜f1e49d4)。
- **テスト**: 回帰テストを 18 件足し、319 件から 337 件になった。修正後は本番と同じビルドで、全部の画面サイズとシナリオを流し直した。
- **確かめて問題がなかったもの**: 提出の取りこぼし(部員 5 人・4,327 件を全件取得と照合して 0 件)、kenkoooo の CORS、PWA のパス、Web フォントを読めないときのヘッダー。

## 方法

### 1. コードの読み込み

次の 3 つの領域に分けて、全ファイルを読んだ。

- データ・ダッシュボード側(取得・キャッシュ・推定・各ページ)
- エディター・コーナーケース生成
- CSS・スマホ・テーマ・計算量ページ

それぞれ、具体的な起き方と重要度を付けて候補を挙げた。型チェック・oxlint・既存のテスト(319 件)は、点検を始めた時点ですべて通っていた。

### 2. Playwright での確認

Playwright 1.64 で、本番(修正前)と、修正後の本番ビルド(`vite preview` + 本番のスナップショット)の両方を動かした。

| 区分 | 内容 |
| --- | --- |
| 画面サイズ | **PC**: Chromium の 1280 / 1024 / 880 / 821 / 761 幅<br>**スマホ**: iPhone 13(WebKit)、iPhone SE 初代(WebKit・320 幅)、Pixel 7(Chromium)、320×568(Chromium・タッチ)、iPhone 13 の横向き(WebKit) |
| テーマ | ライト・ダーク(1280・iPhone 13・320 幅) |
| ページ | トップ・マイページ設定・個人ページ(ふつう・提出の多い人・24 文字の ID・不正な ID)・ランキング(全期間)・エディター(コーナーケースを開いた状態)・計算量(解析後)・存在しないパス |
| 各ページで見たこと | console のエラー、要素のはみ出し(`#root` の clip を外して測る)、横スクロール、タッチ端末の入力欄の文字サイズ(16px 未満だと iOS が拡大する)、ヘッダーの収まり、スクリーンショット |

画面サイズごとの確認に加えて、データを差し替えたり、わざと失敗させたりする個別のシナリオを流した。

- 初心者の合成データでのレコメンド
- 取得に失敗したあとの再読み込み
- 難易度データが取れないときのランキング
- 計算量の範囲の入力と貼り付け
- チャンクの読み込みの失敗
- コーナーケース(密なグラフ・`\frac`・`P_i ≠ i`・0 始まり・「連結とは限らない」)
- 実際の Wandbox / Compiler Explorer での実行(正常・コンパイルエラー・出力の打ち切り)
- ヒートマップのホバーとタップ
- 最初の描画のテーマ
- 別の人のページへの移動
- 部員以外の ID
- 日本語の変換入力(CDP の `Input.imeSetComposition`)
- スクロールバーの表示(`--hide-scrollbars` を外す)
- Web フォントを読めないときのヘッダー
- 開発サーバーのプロキシ経由での取得

ほかの kenkoooo の負荷について:

- 画面サイズごとの確認では、kenkoooo への差分の取得を「新しい提出なし」に差し替えた
- 実際に kenkoooo に問い合わせたのは、取りこぼしの照合と開発サーバーの確認だけ

確認用のスクリプトはプロジェクトの外に置き、`package.json` には Playwright を足していない。

## 見つかった不具合と対処

**重要度**:

- 高: 機能が使えない、または誤った結果を出す
- 中: 条件がそろうと誤る・使いにくい
- 低: 見た目や記述のずれ

**確かめ方**:

- 画面: 本番で再現した
- node: 実データ・実コードで再現した
- 読み: コードを読んで確定した

## 確かめて問題がなかったもの

- **提出の取りこぼし**: 部員 5 人(計 4,327 件)のスナップショットを kenkoooo の全件取得と照合し、取りこぼしは 0 件。ページ送り(同じ秒は重複込みで取り、id で除く)も正しい。
- **kenkoooo の CORS**: すべてのファイルで `access-control-allow-origin: *` を返す。本番のブラウザから直接読める(atcoder.jp は許可しないので、レートはスナップショットから読む)。
- **PWA のパス**: favicon・apple-touch-icon・manifest は、ビルドで相対パスに書き換わる。GitHub Pages の `/shojin-dashboard/` 配下で 200 を返す。
- **ヘッダー**: Web フォントを読めなくても、761〜1024 幅で 1 行に収まり、テーマのボタンと重ならない(Chromium・WebKit)。
- **ヘッダーのタブ**: 360px 以上の幅では横スクロールせずに 1 行に収まる(はみ出すのは 320px だけ)。
- **0 始まりの頂点**: `0 ≤ u_i < v_i ≤ N-1` は 0〜N−1 の頂点で作られていた(エージェントが挙げた「頂点 N が出る」は再現しなかった)。
- **その他**: 個人ページのグラフ(Recharts)は幅に合わせて縮む(ライブラリのコードで確認)。JST の日付の区切り・月曜始まりの週・ストリーク・40〜75% のレコメンドの絞り込みも正しい。
