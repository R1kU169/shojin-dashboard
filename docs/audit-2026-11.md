## 直さなかったもの(既知の限界)

計算量の解析器について、次の点は今回は直していない。どれも普通のコードでは起きにくいか、表示が控えめになるだけ。

- `[[[…]]]` のような深い入れ子の括弧は、段数が増えると時間が倍々になる(20 段で約 1 秒)。
- 2,000 項を `+` でつないだ1つの式で、スタックがあふれる。
- 範囲の欄に「1 ≤ L ≤ R ≤ N」のような連鎖を入れると読めない。`10^9+7` も読めない。
- Java の `for (int[] e : g.get(v))` を隣接リストとして読まない。
- 関数の引数で受け取った値が、範囲を入れる変数として出ることがある。
- `while (q--)` のクエリの回数に「マルチテストです」の案内が出る。

ほかに、次の点がある。

- iPhone(WebKit)で個人ページを開いたとき、AtCoder Problems への通信の失敗が1回だけ記録された。
  - 同じ条件で開き直すと 200 で成功し、CORS のヘッダーも付いていた。
  - 点検で続けて通信していた時間帯の、AtCoder Problems 側の一時的な失敗とみている。
  - 画面は、取得できなかったときの案内を出して動き続ける。
- 部員でない人の個人ページは、全提出を集めるので時間がかかる(chokudai さんで 1,000 件以上)。仕様どおり。
