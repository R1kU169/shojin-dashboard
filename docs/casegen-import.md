# コーナーケースの「入力」「制約」の取り込み(ブックマークレット・まるごと貼り付け)

## 背景

エディターのコーナーケースは、問題ページの「入力」と「制約」を読んで境界の入力を作る。
はじめは、この2つを問題ページで別々に範囲選択して2つの欄に貼る必要があった。
部員から「入力がとても大変」「どう入力したらいいか分からない」という声があった。いちばん大事なのは、
**参加中のコンテストの問題で、その場ですぐ使えること**。

## 決定事項(2026-11-08)

| 論点 | 決定 |
| --- | --- |
| 主な読み込み方 | ブックマークレット「精進ボードに送る」。AtCoder の問題ページで押すと、その問題を連携して入力と制約を読み込み、ケースまで作る |
| まとめて取り込む | 「問題一括表示」(`/contests/<id>/tasks_print`)で押すと全問題を取り込み、エディターの記号(A〜G)で切り替える |
| 登録できないとき | 問題ページで全選択してコピーし、1つの欄に貼る。「入力」「制約」の見出しを探して切り出す |
| 手で書く | 「入力と制約を自分で書く」で、これまでの2つの欄を出す(読み込んだあとは畳んで「見る・直す」に入れる) |
| 問題ページを自動で集めるか | 集めない(下記) |

### 問題ページを自動で集めない理由

6時間ごとの自動更新(GitHub Actions)で問題ページを集め、公開サイトに置く案も検討した。
問題ページ(`/contests/*/tasks/*`)は robots.txt では禁止されていない。それでも、次の理由で採らなかった。

- コンテスト中に間に合わない。問題は開始まで見えず、更新は6時間ごと。
- 集めたものは公開サイトに置くことになる。コンテスト中に問題の内容を公開するのは、AtCoder のルールに反する。
- 終わったコンテストでも、全問題の問題文(入力・制約)を公開サイトに載せるのは、AtCoder の利用規約(無断転載の禁止)に触れる恐れがある。

ブックマークレットなら、問題文はユーザーのブラウザの中で AtCoder のタブからエディターのタブへ渡るだけで、どこにも公開されない。

## ブックマークレットのしくみ(`src/lib/bookmarklet.ts`)

1. 押したページが `atcoder.jp/contests/<id>/tasks/<問題ID>` か `…/tasks_print` でなければ、案内を出して終わる。
2. `#task-statement` の日本語の部分(`.lang-ja`。古い問題で無ければ全体)を複製する。
   表示用の数式(KaTeX)は、中に残っている元の TeX(`annotation[encoding="application/x-tex"]`)に置き換え、
   入力例・出力例の節は除く。
3. 「問題一括表示」には問題ID が載っていないので、同じオリジンの問題一覧(`/contests/<id>/tasks`)を1回だけ読み、記号から問題ID を引く。
   読めなければ `<コンテストID>_<記号の小文字>` にする。
4. `{ v: 1, contest, current, tasks: [{ task, title, html }] }` を JSON → UTF-8 → base64url にする。
   それを `<ボードの URL>#/editor?import=…` として、名前付きのウィンドウ `shojin-editor` で開く。
   - URL の `#` より後ろはサーバーに送られない。
   - ポップアップと見なされて止められないように、問題一覧を読む前にウィンドウを開いておき、あとで行き先を書き換える。
   - `noopener` は付けない。付けると、同じ AtCoder のタブから続けて押したときに、前に開いたエディターのタブを名前で見つけられない。

ブックマークレットは自己完結にしてあり、外部のスクリプトは読まない。AtCoder にログインしているページの中で動くので、
ボードの側が改ざんされても、登録済みのブックマークレットの動きは変わらないようにしている。
そのかわり、中身を変えたら登録し直してもらう必要がある。データの形を変えるときは `v` を上げる。

## 受け取り(`src/pages/EditorPage.tsx`・`src/lib/editorStore.ts`・`src/lib/importPayload.ts`)

- `decodeImport` が形を確かめる。URL は誰でも作れるので、ID の形(`^[A-Za-z0-9_-]{1,64}$`)・20問まで・大きさを確かめる。
  問題文の HTML は DOMParser で文字列にするだけで、ページに HTML として入れない。
- 各問題の HTML を `statementHtmlToText`(`src/lib/katexPaste.ts`)で行ごとの文字列にし、
  `splitStatement`(`src/lib/casegen/statement.ts`)で「入力」「制約」を切り出して、問題ごとの保存キーに書く。
  同じ問題文を取り込み直したときは、範囲の手直しを残す。
- どの問題を連携するか:
  - 問題ページで押したときは、その問題。
  - 「問題一括表示」で押したときは、いま連携中の問題が含まれていればそのまま、なければ最初の問題。
- 履歴に問題文を残さないよう、URL から `import` を消す。
- コーナーケースのカードを開き、`spec` が新しい入力に追いついたところでケースを1回作る。
  `spec` は `useDeferredValue` 経由なので、すぐに作ると前の問題の `spec` で作ってしまう。

### タブ間の受け渡し

自分で開いたエディターのタブは、AtCoder のタブから名前では見つけられない(ブラウジングコンテキストグループが別)。
そこで、取り込みのために開かれたばかりのタブでは、次のようにする。
ページを開いたときの `location.hash` は `src/lib/boot.ts` で覚えておき、`import=` を含むかで判定する。

1. `BroadcastChannel("shojin-editor")` で他のエディターのタブに知らせる。
2. 0.5 秒以内に返事があれば、「ほかのタブで開いているエディターに読み込みました」と出して自分を閉じる。
3. 返事がなければ、このタブがそのままエディターになる。

受け取ったタブは、保存された問題と問題文を読み直して返事をする。自分が送った知らせに自分で返事をしないよう、タブごとの印を付けている。

## まるごと貼り付け(`src/components/CaseGenerator.tsx`)

- クリップボードの HTML を `statementHtmlToText` にかける。数式は KaTeX の annotation から TeX に戻す。
- HTML が無ければプレーンテキストを使う。
- `splitStatement` は、行全体がちょうど見出しの語の行だけを見出しとみなす(同じ語は文中にいくらでも出るため)。
  ページ全体のコピーにはメニューや英語版も混ざるので、日本語の見出しを優先する。
  - 入力例・出力例・部分点・注意などの見出しで止める。
  - 「入力は以下の形式で標準入力から与えられる。」の行は落とす。
  - 入力の節が説明の文だけ(出力だけの問題)なら、入力の形式は無いことにする。
- プレーンテキストは、KaTeX の表示が行末の空白や空白だけの行で添字・累乗を表している。
  そのため、切り出すときに行の中身は削らない(`tex.ts` が元に戻す)。

## あわせて直した読み取りの誤り

- 「Q は 1 以上 2 × 10^5 以下」の上限を 10^5 と読んでいた。値の中の空白(TeX の `2 \times 10^5`)の手前で切っていたため。
  日本語や句読点の手前までを1つの式として読むようにした。
- 古い問題の `10 \ 000`・`1 \ 000 \ 000 \ 000`(TeX の桁区切り)を2つの数に割っていた。
  数字の間の `\ ` `\,` `~` `{,}` は、後ろが3桁ちょうどのときに詰める。

## 確かめたこと

  - abc481_c のページでブックマークレットを評価 → エディターが C を連携し、Q 1〜2×10^5・s の長さ 1〜10 を読み、ケースを自動で作った。
  - abc481 の「問題一括表示」→ 7問を取り込み、A〜G の切り替えが出た。
  - abc100_c のページ全体の HTML を貼り付け → N 1〜10^4・a_i 1〜10^9 を読んだ。
  - エディターのタブを開いたまま取り込み用の URL を別のタブで開く → 元のタブが読み込み、新しいタブは受け渡しの案内を出した。
  - 前にボタンで開いたタブに `#` 以降だけ変わって届いたとき → ページを読み込み直さずに取り込んだ。
