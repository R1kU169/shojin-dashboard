# コンテストタブ(/contest)の追加

## 背景

コンテストのあと、部員どうしで「誰が何位で、どの問題まで解けて、どんなコードだったか」を確かめるのに、
AtCoder の「すべての提出」で気になる人のユーザー名を1人ずつ手打ちしていた。
登録部員全員の結果を1画面で見られるタブを足す。

## 決定事項(2026-10-25)

| 論点 | 決定 |
| --- | --- |
| 置き場所 | 新しいタブ「コンテスト」(`#/contest`, `#/contest/<コンテストID>`)。トップの「コンテスト予定」カードに直近の結果へのリンク |
| コード | アプリ内には出さない。表のマスと比較の表から AtCoder の提出ページへリンクする(下記「読まないもの」) |
| 公式順位の鮮度 | 6時間ごとのスナップショットに加え、土日の夜 22:45・23:00・23:15・0:00(JST)にも作り直す |
| 対象のコンテスト | 直近1年に開始した、5時間以内の Rated のコンテスト(AHC を除く)。部員が参加したものと、開始から7日以内のもの |

## データの出どころ

| 表示 | 出どころ | いつから出るか |
| --- | --- | --- |
| 問題ごとの AC・時間・ペナルティ・得点 | 部員の提出(AtCoder Problems。スナップショット + ブラウザから差分) | AtCoder Problems に提出が載ってから(終了直後〜数分) |
| 公式の順位・パフォーマンス・レート変化 | atcoder.jp `users/<id>/history/json`(スナップショットが取る。Unrated の参加も含む) | レート更新のあとの最初のスナップショット |
| コンテストの開始・長さ・問題 | kenkoooo `resources/contests.json` / `contest-problem.json`。kenkoooo にまだ無い直近のものは atcoder.jp/contests/ の表 | スナップショット。問題セットが無いときは部員の提出から作る |

公式成績は、もともとスナップショットがレート推移のために読んでいた参加履歴から作るので、atcoder.jp へのリクエストは増えない
(増えるのは土日の夜の更新回数ぶんだけ)。

### 読まないもの

- `contests/<id>/standings/json`(順位表): ログインが必要。順位表は AtCoder へのリンクで出す
- `contests/<id>/submissions?f.User=`(提出一覧): ログインが必要
- `contests/<id>/submissions/<id>`(提出ページ): ブラウザ以外には 403 を返し、robots.txt でも `/contests/*/submissions/` が禁止されている。
  `X-Frame-Options: SAMEORIGIN` で埋め込みもできない。ブラウザで人が開くのは問題ないので、リンクだけにする
- `contests/<id>/results/json`: 公開だが ABC で約 5MB。参加履歴と同じ情報なので使わない

## 計算の定義(`src/lib/contest.ts`)

- **時間内の提出**: そのコンテストに出した提出で、開始 ≤ 提出時刻 < 終了(終了ちょうどは時間外)
- **得点**: 問題ごとに時間内の最高点。部分点にも対応する
- **ペナルティ**: 最高点に最初に届いた提出より前の誤答の数。CE・IE・WJ・WR は数えない。得点していない問題の誤答は数えない
- **時間**: 最後に得点した時刻 + ペナルティ × 5分(AtCoder の順位表と同じ)
- **解き直し**: 時間内に AC しなかった問題を、終了後に AC した最初の提出(ADT など別のコンテストでの提出も含む)
- **部内の順位**: 参加者全員に公式成績があれば公式の順位の順(表示は「公式」)。そろっていなければ得点の高い順 → 時間の短い順(表示は「暫定」)。
  同点は同じ順位

## スナップショットのファイル(`scripts/build-snapshot.mjs`)

| ファイル | 中身 |
| --- | --- |
| `contests.json` | `ClubContest[]`(開始の新しい順): id・名前・開始・長さ・Rated 対象・参加した部員の数・問題(記号順) |
| `contest-results.json` | `{ コンテストID: { 部員ID(小文字): { place, perf, oldRating, newRating, rated } } }`。`contests.json` に載るコンテストの分だけ |
| `upcoming.json` | 予定の ABC/ARC/AGC。長さ(`duration`)と Rated 対象(`rate`)を足した。スナップショットの後に始まったコンテストもタブで選べるようにする |

取得に失敗したときは、ほかのファイルと同じく前回分を使う(kenkoooo の一覧は前回の `contests.json`、公式成績はその部員の前回分)。

## ブラウザ側

- `getContestList()` / `getOfficialResults()`(`src/lib/cache.ts`): IndexedDB に 10 分キャッシュする(土日の夜の更新をすぐ拾えるように)
- 部員の提出の読み方はランキングと同じ(手元のデータで先に並べ、古い人だけ kenkoooo から差分を順に取る)。
  ただし、終了の3時間後より後まで取れている人はそのコンテストのためには取り直さない
- 開催中・開始前のコンテストは結果を出さない(終了後に見るページ)
